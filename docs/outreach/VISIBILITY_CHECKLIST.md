# Visibility checklist

Done in the repository: topics, a one-line description, a project website with results and a maintainers page, a sitemap, share-card tags, contributor guide, starter issues, issue and PR templates.

Needs the owner (settings or accounts, not code):
- [ ] Repository **Settings > General > Social preview**: upload `assets/ounce-core-vista.png` (1280x640 works best).
- [ ] Repository **About**: set the website to https://hffgzktbcc-blip.github.io/ounce-core/ if it is not already.
- [ ] **Settings > Security**: enable private vulnerability reporting (SECURITY.md refers to it).
- [ ] Pin the repository on your GitHub profile; add a profile README line linking it.
- [ ] Publish `docs/outreach/BLOG_POST.md` somewhere with a stable URL (dev.to, your site, or a GitHub Discussion), then post from `LAUNCH_POSTS.md`, one place per day.
- [ ] Cut a GitHub **release** with notes (the first with the new direction), so the release feed is current.
- [ ] Submit the site to Google Search Console (adds the sitemap) and Bing Webmaster Tools.
- [ ] Reply to the first outside issue or discussion within a day; that response is what builds trust.

Measure what matters: outside people who run a harness, issues from people who are not you, and program requests. Not stars.
