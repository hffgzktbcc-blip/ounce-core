# Ounce Core v0.7.0 (draft, not published)

Draft only. No version is tagged, no assets are published and no check is claimed beyond
what is cited here. The file is named `-draft` on purpose: `release.yml` reads
`docs/releases/<tag>.md`, so renaming it to `v0.7.0.md` is the step that makes a tag use it.

## What changed since v0.6.1

- **Static Linux ELF coverage.** `run-elf` answers `sched_getaffinity` (one CPU, validated the
  way Linux validates it). With that, the pinned xxHash, cJSON and zlib harnesses run as
  static musl ELFs and match a fresh x86-64 host build on Tier-3 and Tier-4 (PR #277,
  checked on Linux). The three-host ELF job now covers all four libraries (LZ4, xxHash,
  cJSON, zlib); its first hosted result is the evidence, not this file.
- **Quiet-NaN operand order in the vector-FP harness.** FADD/FMUL operand order is pinned in
  `fp_cases.c`; the earlier "difference" was a compiler operand swap, not a hardware
  difference (PR #272, hosted arm64 and macOS Differential jobs passed). The FPSR[31:28]
  question in #257 is still open.
- **CLI banners print the real crate version** instead of a hardcoded `v0.3.0` (#288).
- **Behavior-preserving clippy cleanups** in `src/` (#287) and new community guides and
  glossary (#287).
- **Native Mac app, local developer preview.** `scripts/package_macos_app.py` packages the app
  with a manifest and checksums (#290). See below for what is and is not shipped.

## The Mac app is not in the release assets

Per `docs/PROVENANCE_OWNER_DECISIONS.md` item 4 (objc2 and Apple SDK terms), no prebuilt
macOS app is attached to a GitHub release. Build it from source with
`scripts/build_macos_app.sh`, or use the CI `macos-app-preview` artifact, which is a
developer preview: ad-hoc signed, not notarized, Gatekeeper warns on first open.

Checked on an Apple Silicon Mac (macOS 26.6.2) for the preview built by CI: archive
checksums, valid ad-hoc signature, the bundled runtime's self-test (36 checks), hello.nro on
tier3 and tier4 (9,067 instructions each), launch and first-run window, and "Try the Demo".
**Not checked:** running a chosen program from the window, the failure-diagnosis card,
Verify against Host from the window, cancel and relaunch, other window sizes, tier4 inside
the GUI, and the first-open Gatekeeper experience.

## Unchanged

CLI archives, notices, checksums and attestations are produced the same way as v0.6.1 for
Linux x86-64, macOS arm64 and Windows x86-64. No claim of independent reproduction, general
libc compatibility, or Neoverse conformance is made.
