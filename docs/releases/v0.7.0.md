# Ounce Core v0.7.0

Adds a local verification workbench and an instruction-level disagreement finder, fixes
several emulator and CLI behaviours, and widens the differential suite. The verification and
conformance claims are unchanged: nothing here claims independent reproduction, Neoverse
conformance or general libc compatibility.

## Added

- `ounce-core ui`: a local workbench on 127.0.0.1. Drop a homebrew `.nro`, run it on Tier-3
  and Tier-4, optionally compare with this computer's CPU, and see the first differing
  output line. It is one run, not a proof.
- `ounce-core diverge <program.nro>`: replays a sample of register-only instructions on this
  machine's CPU and names the first one where Ounce-Core disagrees (AArch64 hosts only; see
  `docs/DIVERGE.md` for limits). The workbench shows it as an "Instruction check" card.
- Static Linux ELF coverage: `run-elf` answers `sched_getaffinity`, so the pinned xxHash,
  cJSON and zlib harnesses run as static musl ELFs and match a host build on Tier-3 and
  Tier-4.
- QuickJS (46 scripts), QOI, tiny-AES-c, heatshrink, stb_image, LodePNG and a long-running soak
  workload join the differential suite; each matches a host build on Tier-3 and Tier-4.
- TestFloat vectors for `fuzz-replay`; every committed `.nro` replayed on the host CPU
  (22k instructions, 0 disagreements).
- Community guides, contributor onboarding, a citation file and a nightly fresh-seed fuzz.

## Fixed

- `FMAX`/`FMIN`/`FMAXNM`/`FMINNM` honour FPCR flush-to-zero and default-NaN. Before, 1,208 of
  4,800 replayed operand sets disagreed with the host CPU when either was set; now none do.
  Tier-4 no longer compiles scalar FMAX/FMIN natively.
- `run`/`run-nro --cpu=tier3|tier4` now selects that engine for homebrew programs. It was
  previously ignored, so earlier "Tier-3"/"Tier-4" NRO differential columns had run on the
  interpreter.
- The qc-flag harness masks FPSR[31:28] (RES0 without FEAT_AA32), resolving #257.
- CLI banners print the crate version instead of a hardcoded `v0.3.0`.
- Workbench on Windows and Linux (results folder, browser opener, closed stdout) and an
  `ounce-nce` arena test flake.

## The Mac app is not in the release assets

Per `docs/PROVENANCE_OWNER_DECISIONS.md` item 4 (objc2 and Apple SDK terms), no prebuilt
macOS app is attached to a GitHub release. It can be built from source with
`scripts/build_macos_app.sh`. It is a developer preview: ad-hoc signed, not notarized, and
its live-window acceptance (running a chosen program, failure-diagnosis card, host
verification, cancel/relaunch, Tier-4 in the GUI, Gatekeeper first open) is not claimed.

## Unchanged

CLI archives, notices, checksums and attestations are produced the same way as
[v0.6.1](https://github.com/hffgzktbcc-blip/ounce-core/releases/tag/v0.6.1) for Linux
x86-64, macOS arm64 and Windows x86-64. No new legal review or third-party grant is claimed.
