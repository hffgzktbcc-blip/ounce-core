## ounce-core v0.9.0

### `ounce.run.v1`

`run` and `run-nro` write the report when `--report-json` or
`OUNCE_REPORT_JSON` is set. The process still exits 1 when the guest does not
stop cleanly; the file is written first.

```sh
ounce-core run-nro tests/fixtures/nro/hello/hello.nro fixture \
  --present=headless --report-json=run.json
```

Fields written today: `schema`, `engine` (`ounce-core`), `engine_version`,
`tier`, `silent_fallback`, `stop_kind`, `exit_code`, `pc`, `opcode`,
`fault_addr`, `svc_id`, `break_result`, `insns_executed`, `message`.
Stop kinds and exit codes match `docs/OUNCE_RUN_V1_SCHEMA.md` for this
engine, including splitting a fault into unimplemented instruction (10),
memory fault (11), or other CPU error (12).

Checked once on this Linux x86_64 host, release build of `2c52649` with
`native-jit`: `run-nro tests/fixtures/nro/hello/hello.nro fixture --present=headless --report-json=run.json`
exited 0, printed `result=0x00000EEE`, and wrote `stop_kind=clean_exit`,
`exit_code=0`, `tier=tier3`, `silent_fallback=false`, `insns_executed=9335`,
`engine_version=0.8.2` (the crate version has not been bumped). The same file
with no guest argument still exits 0 and prints `result=0x0BAD0008`.
`inspect` on a plain-text file exited 1. `inspect` on `hello.nro` exited 0.

Limits, so a consumer does not trust fields the binary does not fill:

- `silent_fallback` is always `false`, including when Tier-4 was requested and
  Tier-3 ran.
- `frames_presented` and `framebuffer_hash` are absent. The roadmap asks for
  both, with the hash taken from guest pixels before any HUD, before anyone
  compares engines on that hash.
- `run-elf` accepts host flags in `main` and then handles its own arguments.
  `--deterministic` is implemented there (fixed guest clock). `--report-json`
  is not written by the ELF runner. Wiring it is a Q2 item.
- `--deterministic` and `OUNCE_DETERMINISTIC=1` or `true` set a flag that the
  homebrew kernel does not read. Homebrew `run` / `run-nro` still use the host
  clock. The corpus runner sets a deterministic clock on its own.
- `--audio=null` and `OUNCE_AUDIO=null` skip the host audio device. Headless
  presentation already did.

### `inspect`

A file that is not NRO0 or NSO0, a truncated NSO0 header, or an NRO0/NSO0 that
fails to load now exits 1 with a reason (`#385`, `#433`). A loose directory is
still inspected as before.

### Linux ARM64 ELF matrix

`python3 scripts/run_linux_arm64_matrix.py` selects harnesses from
`docs/verify/differential.json` and aggregates `verify_linux_elf.py`. The new
CI job runs on `ubuntu-24.04-arm` with `qemu-user` and Zig 0.17.1, 45-minute
timeout, and uploads the JSON report. It has not gone green on `main`.

`run-elf` is documented as bounded-verified for static musl AArch64 `ET_EXEC`
only. Dynamic PIE, threads, sockets, and glibc compatibility stay out of scope.

### Also since v0.8.2

Roadmap documents only (`#441`, `#443`). No CPU, loader, or JIT change is in
this range, so instruction behaviour relative to v0.8.2 should be unchanged.
That is a claim about the diff, not a new conformance result.

### v0.8.2 changelog gap

`CHANGELOG.md` had no 0.8.2 section. The tag commit only changed `Cargo.toml`,

## ounce-hb v0.1.0

Since v0.0.2, on `main`, not in the v0.0.2 release archive.

### `doctor`

`ounce-hb doctor` and `ounce-hb doctor --json` report host OS and architecture,
whether this machine can do AArch64 hardware replay (Linux or macOS on
aarch64), and the path and `--version` line of `ounce-core` and, if present,
`ounce-runtime`. JSON uses `"schema": "ounce.doctor.v1"`. Exit 0 if at least
one engine binary is found, exit 3 if neither is. It does not look for
`DEVKITPRO`, `devkitA64`, or `cargo-nx`. That check is still an after-tag
roadmap item.

### `run --auto`

`--auto`, or `--backend auto`, runs `ounce-runtime` when that binary can be
found and otherwise runs `ounce-core`. If the runtime report says
`silent_fallback` or the diagnosed exit is 10 through 15, ounce-hb runs
ounce-core as well. Identical diagnoses are labelled Guest Bug. Different
diagnoses are labelled Runtime Divergence and an `ounce.repro.v1` bundle is
written to `ounce-repro.json`. There is no `--timeout` flag and no `--json`
flag on `run`. The time limit remains `OUNCE_HB_TIMEOUT_SECS` (default 60,
maximum 86400). Guest arguments that start with `-` are still refused.

### `repro`

`ounce-hb repro [--backend <core|runtime|path>] <bundle.json|dir>` loads one
manifest, or every `*.repro.json` and `ounce-repro.json` in a directory, and
checks the selected backend (default `core`) against the recorded `stop_kind`
and `exit_code`. Exit 0 if all pass, 1 if any fail, 2 if the input is missing
or not a valid manifest. It does not compare `framebuffer_hash`. The roadmap
asks for that comparison later.

### `setup-ounce`

`.github/actions/setup-ounce` on `main` downloads release archives of ounce-hb
and ounce-core (checksums checked) and, if `install-runtime` is `'true'`,
ounce-runtime (checksum not checked). It then runs `ounce-hb doctor --json`.

That last step does not succeed against the published v0.0.2 archive, because
v0.0.2 has no `doctor` subcommand. The action is usable once a release that
contains `doctor` exists, or when it is pointed at a binary that has the
command. Linux is selected as `linux-x86_64` only. linux-arm64, `install-hb`,
Windows `pwsh` extraction, and runtime checksum verification are the open
changes in `#40`, not the behaviour of `main` today.

The release workflow on `main` still triggers on `v*`, so a floating
`setup-ounce@v1` tag would also start a binary release. `#40` narrows the
filter. Do not publish `setup-ounce@v1` before that change is on `main`.

## ounce-runtime v0.6.0

Since v0.5.0, on `main`, not in the v0.5.0 release archive. GPL-3.0-or-later.
This section is a description of the public CLI, not a port of that code.

`run` / `run-nro` accept the same `--report-json`, `--audio=null`, and
`--deterministic` spellings, and the same `OUNCE_REPORT_JSON`, `OUNCE_AUDIO`,
and `OUNCE_DETERMINISTIC` variables. The report uses `"engine": "ounce-runtime"`
and adds two fields ounce-core does not emit:

- `frames_presented` — count from the display, or 0 when there is no display.
- `framebuffer_hash` — `fnv1a64:` plus 16 hex digits of the presented front
  buffer after at least one frame, otherwise JSON `null`.

`silent_fallback` is true when Tier-4 or NCE was requested and the run did not
use that tier. `--deterministic` is stored the same way as in ounce-core: the
flag is accepted, and this tree does not show the homebrew kernel reading it.

`tests/repro_ingestion.rs` loads an `ounce.repro.v1` manifest and runs
`run-nro` with `--present=headless`, `--audio=null`, `--deterministic`, and
`--report-json`.

Contract gap to decide before calling the two reports interchangeable: on the
runtime homebrew path, every `VmStop::Fault` is recorded as `cpu_error` / exit
12, with `opcode` and `fault_addr` left null. ounce-core splits that stop into
exit 10, 11, or 12 and fills the matching field. `ounce-hb run --auto` treats
differing diagnoses as runtime divergence. A guest that faults can therefore
be labelled a divergence when the two engines stopped for the same guest
reason and reported it differently. This draft does not change either engine.

The hash is of the presented front buffer. The roadmap still requires a
pre-HUD guest-pixel hash before that field is used as a parity oracle. Do not
treat a hash mismatch as an engine bug until that lands.

`#13` is the remaining license, notice, and release-workflow work for this
tag. The v0.5.0 archive set does not include a linux-arm64 build; `#13` adds
that row to the README ahead of the workflow change.
