## ounce-core v0.9.0

Changes through `6a4ccb8` since v0.8.2:

- `run` / `run-nro` emit `ounce.run.v1` with `--report-json` or
  `OUNCE_REPORT_JSON`; guest stdout remains separate (#439).
- `inspect` rejects invalid or unsupported executable files with a nonzero exit
  (#433), and the quick-start guide documents the current CLI (#448).
- The Linux ARM64 ELF matrix runs pinned harnesses at multiple optimization levels
  (#440); release infrastructure adds Linux ARM64 archives and consistent checksums
  (#442).
- The software-keyboard applet returns a deterministic cancellation rather than
  hanging (#446). Interactive text entry is not implemented by this change.
- CPU changes cover scalar FMULX (#445), FCVTXN/FCVTXN2 round-to-odd (#449),
  vector SQRDMLAH/SQRDMLSH (#450), FCADD (#451), and half-precision vector FMOV
  immediate decoding (#444).
- Family roadmaps are retained under `docs/roadmap/` (#441, #443).

PR #452's interpreter deadline-polling optimization is still open and is **not**
part of this recorded main revision or its measured release scope.

### Existing contract limits

- Core's `silent_fallback` remains false even where Tier-4 requests fall back to
  Tier-3. Core does not yet emit `frames_presented` / `framebuffer_hash`.
- `run-elf` does not emit `ounce.run.v1` reports. Its deterministic clock behavior
  is bounded to the documented ELF path; accepting `--deterministic` on a homebrew
  command does not establish deterministic homebrew scheduling.
- The runtime's presented-buffer hash is not yet a pre-HUD cross-engine parity
  oracle. Differing fault classifications across engines can also cause `--auto`
  to report a divergence for the same underlying guest fault.
- No new compatibility, independent-rerun or performance claim is made here.

## Sibling release scope

These sections describe public commands and packaging only. No GPL runtime source
or implementation patterns are copied into this MIT repository.

**ounce-hb v0.1.0:** the already-landed `doctor`, `repro` and `run --auto` workflow
is followed by the merged #40 release/setup action changes: Linux ARM64 selection,
Windows extraction, optional hb installation, runtime checksum verification, and
numeric release-tag filtering. The published v0.0.2 binary does not contain `doctor`;
shipping the new archive remains necessary before advertising that installed flow.
`run --timeout`, `run --json`, framebuffer comparison and wider toolchain checks
remain subsequent roadmap work.

**ounce-runtime v0.6.0:** public run reports include engine/tier identity,
`frames_presented` and `framebuffer_hash`; #13 adds the coordinated release workflow,
notices and Linux ARM64 archive target. Contract limits above remain explicit.
These notes do not claim the v0.6.0 archives already exist.
