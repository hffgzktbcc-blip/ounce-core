# ounce-core v0.10.0 — release notes (draft, not published)

**Status: draft.** Nothing is tagged or published. This page lists what is on `main` since v0.9.0 and what is still
needed before a tag. The owner decides when to publish.

Changes since [v0.9.0](v0.9.0.md) (tagged at `4b63f7a`): 69 commits on `main`, up to `1553f9d` (#503).
The Cargo version is still `0.9.0`; the bump is a release step (see "Before tagging").

## What changed for users

### Machine-readable run reports (`ounce.run.v1`)

All additions are new keys. No key was removed or renamed. See the [schema](../OUNCE_RUN_V1_SCHEMA.md).

- `frames_presented` and `framebuffer_hash` (#460). 3D frames are hashed too when the run is `--deterministic` or
  headless (#486).
- `lr` and `sp` (link register and stack pointer at the stop), set exactly when `pc` is (#475, first part). Function
  names and stack frames are **not** done; they need a new dependency, which is an owner decision.
- `audio_frames_mixed` and `audio_hash` (#478). They are counted as audio is mixed, so a headless run and a run with a
  sound device report the same values. A program with no audio reports `0` and `null`.
- `run-elf` now writes the same report, plus a new `guest_exit_status` for the program's own exit status, and
  `--dump-regs` (#473).

### Running programs

- `--max-frames N` and `--press BUTTON@FRAME` for scripted runs (#458).
- Guest arguments after `--` now reach the program unchanged, including ones that start with `-`. An unknown option
  before `--` exits 2 (#487). An empty guest argument is refused with exit 2.
- `--deterministic` now fixes the guest clock for homebrew, so the same program executes the same number of
  instructions every run. Previously `input.nro` gave 7,602 or 8,207 (#479).
- Guest debug output is flushed as it is written, so a hung program's last partial line is no longer lost when an
  outer timeout kills it (#476).
- `--sdmc` copy-on-write overlay and RomFS verification (#459).

### Verification tools

- `ounce.trace.v1`: a bounded step trace and `ounce-core trace-diff`, which reports the first differing step
  ([schema](../OUNCE_TRACE_V1_SCHEMA.md), #477). Registers only; no memory changes are recorded yet.
- A draft compatibility contract and tests that pin the report keys, exit codes and flags by running the binary
  ([contract](../CONTRACT_V1.md), #481). This is a draft, **not a freeze**.
- Paper checks (#503): `docs/verify/papers/` reproduces the Philox known-answer vectors, a statistical smoke battery for it,
  and the Ogita-Rump-Oishi accurate-sum bounds and Table 6.2, as ARM64 programs run with `run-elf`. Tier-3 on x86-64 only,
  not in CI. They show the numbers match the papers', not that the papers' wider claims hold.
- Instruction budgets: committed fixtures run with `--deterministic` and fail CI if the instruction count goes up
  more than 2% ([guide](../INSN_BUDGETS.md), #479).

### CPU and Linux ELF support

- New instructions: `FJCVTZS`, and the vector fixed-point converts `SCVTF`, `UCVTF`, `FCVTZS` and `FCVTZU` (#469).
  `FJCVTZS` now clears Z for a denormal flushed to zero by FZ, as hardware does (#499).
- Scalar `FRECPE`, `FRSQRTE`, `FRECPS`, `FRSQRTS`, and `FRINT32` / `FRINT64` (#466).
- Linux identity and process syscalls, `gettimeofday`, `close` and `sched_yield` (#468).
- The Linux ARM64 ELF matrix grows from 28 to 45 harnesses with 17 new first-party static workloads (#474, #496).
  The goal is 50 or more, so this is partway.
- Whole-program FP workload: 199 ops (was 48). Only the original 48 gate CI (#488).

### Supply chain and CI

- Release builds write an SPDX 2.3 SBOM per target, listed in `SHA256SUMS` (#480).
- Every workflow action is pinned to a commit SHA (#480, #501). The six release, pages and coverage refs that were
  still tags are now pinned, and `scripts/check_action_pins.py` has an empty pending list.
- A new ARM64 CI gate runs `FJCVTZS` natively and through `run-elf` on Tier-3 and Tier-4 and fails on any difference,
  so it cannot pass without hardware (#501).
- Zero compiler and clippy warnings, enforced in CI (default, `native-jit,nce` and `gpu-present` features). `rustfmt`
  is enforced too (#500).
- Minimum Rust version corrected to 1.89 for the default build, and checked in CI. `gpu-present` needs 1.90 and
  `native-jit` 1.97.
- CI also gained job timeouts, caching, an automatic second re-run for jobs that never reached a runner, and a native
  oracle that runs in two shards.

### Fixes

- A fault now counts the instructions that completed before it, so `insns_executed` is no longer `0` for a program
  that faults early.
- In `--deterministic` mode a thread waiting on a timeout now wakes even when another thread is spinning (each
  20,000-instruction slice advances guest time by 1 ms).
- A `gpu-present` build whose GPU window failed to open no longer drops 3D draws.
- `scripts/done.sh '#N'` works on macOS (#484).

## What this release does not claim

- **Hardware agreement is not established for everything new.** `FJCVTZS` and the vector fixed-point converts were
  checked against hand-derived values and, informationally, against `qemu-aarch64`. The native ARM64 comparison for
  them has not been run.
- The 17 new ELF workloads were verified on x86-64 against host builds. They have not yet run on the native ARM64 CI
  job as a recorded result.
- A green CI run or a merged PR is not independent testing. No outside reproduction of these results exists.
- Scalar-SIMD fixed-point converts (`scvtf s0, s1, #n`) and half-precision forms are still undecoded.
- ounce-runtime does not implement `ounce.trace.v1`.

## Before tagging

1. Bump the version in `Cargo.toml` and `Cargo.lock` to `0.10.0`, set `version` and `date-released` in
   `CITATION.cff`, and refresh the matching identities in `docs/RELEASE_NOTICE_REVIEW.json` (the v0.9.0 prep did the
   same).
2. In `CHANGELOG.md`, rename "Unreleased" to "0.10.0 — released <date>" at tag time, and start a new empty
   "Unreleased". Then run `python3 scripts/check_pins.py`: `Cargo.toml`, `CITATION.cff` and the newest dated
   changelog heading must all say `0.10.0`.
3. Check CI on the exact final head, including a passing Linux ARM64 ELF matrix on `main`. A pass on an earlier
   revision does not qualify a later one.
4. Run the release workflow's manual, non-publishing path and inspect the archives, checksums, SBOMs and notices.
5. The owner decides to tag. Tagging and publishing are separate from merging.
6. Update the family roadmap's release line once it is published.
