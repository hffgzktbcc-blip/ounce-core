## Exact question requiring a decision

The declared crate licenses and known notices are retained. In
[upstream issue #826](https://github.com/madsmtm/objc2/issues/826#issuecomment-6103078978),
the maintainer confirms earlier versions have their declared licenses. The
[follow-up](https://github.com/madsmtm/objc2/issues/826#issuecomment-6107377999)
does not confirm exhaustive copyright attribution: other contributors exist.
The inherited Steven Sheldon MIT notice, pinned upstream licensing overview,
project-contributor attribution and subsequently supplied upstream full MIT text
are all retained. A read-only upstream root-notice history check found the known
initial/inherited grant and later licensing clarification/full-text additions;
this is not a claim to establish every contributor's ownership.

The pinned [objc2 licensing overview](https://github.com/madsmtm/objc2/blob/d7d2fa23ceaa5e6096c923b081040e5d81b3b9df/LICENSE.md)
expressly says its Apple-SDK-derived bindings may have licensing implications.
It states: "From reading the license, it is unclear whether distributing derived
works such as these crates are allowed?" This qualification is preserved.

The current [Apple Xcode/SDK Agreement](https://www.apple.com/legal/sla/docs/xcode.pdf),
identifier EA2002, dated 06/08/2026, section 2.4 states that macOS applications and
libraries may be distributed without a separate written agreement so long as they
comply with that agreement. Section 2.2 separately distinguishes the macOS SDK
from other-platform SDKs. The fetched PDF SHA-256 is
`5e6bd16bcba3dd591bde1c57f7c6f19f08a194c84cdc54485c4660f90e2a26ec`.
This application-distribution provision does not itself settle the provenance of
all generated bindings. No additional grant or legal clearance is asserted here.

The CLI archives contain executable code and notices; the explicit packager does
not include SDK headers, SDK framework libraries, Xcode, retail assets, NRO test
fixtures or the historical 72-byte outside program. The normal GitHub source
archives separately contain the current repository tree, including the registered
legacy test fixtures. Rebuild identities are not proof of all fixture ownership.
Tag history remains intact; no historical permission or purge is implied.
