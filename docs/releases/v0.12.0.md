# ounce-core v0.12.0 — release notes (published 2026-11-24)

**Ounce-Core runs supported ARM64 programs on three CPU engines, compares their results with references recorded on real ARM64 hardware, and helps developers investigate differences.**

Version **v0.12.0**, released **24 November 2026**, makes `ounce-core run-elf` usable as a `cargo test` runner for `aarch64-unknown-linux-musl` and fixes a silent atomics bug: before this release, `FEAT_LSE` atomic instructions ran as plain loads and stores. It also adds a first-divergence readout to `trace-diff` and records a dated run of seven widely used open-source libraries.

> **Correction, 25 Nov 2026.** The tagline says results are compared "with references recorded on real ARM64 hardware". The reference differs per suite: an Apple M3 for the `#558` probe and the Big Tech native oracles, `qemu-aarch64` or a native host build for the older sweeps, and a suite's own expected values for s2n-bignum, secp256k1 and libmpdec ([evidence table](../DETAILS.md#where-each-headline-number-comes-from)). The `#558` 595,472-case probe program is not committed. Engine-vs-engine agreement is a regression check, because the engines share one decoder and Tier-3 and Tier-4 fall back to the interpreter. The first-party drivers and build commands for the library runs are now in [`docs/verify/bigtech/`](../verify/bigtech/README.md).

## Highlights

- **Atomics fix: upgrade if you build with `-mcpu=apple_m1` or any LSE target (`#559`).** In v0.11.0 and earlier, `LDADD`/`LDCLR`/`LDEOR`/`LDSET`/`LDSMAX`/`LDSMIN`/`LDUMAX`/`LDUMIN`, `SWP`, `CAS` and `CASP` were decoded as plain loads and stores on all three engines. They returned 0, wrote nothing, and `CAS` reported success without storing, with no diagnosis. They are now implemented, together with `LDAPR`, and checked against an Apple M3. Builds that use load/store-exclusive atomics (the default for generic `aarch64` targets) were not affected.
- **`cargo test` through Ounce-Core (`#557`).** `run-elf -- <elf> [args]` now works, so a `.cargo/config.toml` with `runner = "ounce-core run-elf --"` runs aarch64 musl test binaries. See [QUICKSTART.md](https://github.com/hffgzktbcc-blip/ounce-core/blob/v0.12.0/docs/QUICKSTART.md#cargo-test-for-aarch64-linux-musl-through-ounce-core) for the `RUSTFLAGS` macOS needs.
- **More of Linux for test binaries (`#557`).** `ppoll`, deterministic `getrandom`, file reads, writes, seeks and stats on a bounded in-memory `/tmp` and `/var/tmp`, plus `/dev/null` and `/proc/self/auxv`, and opt-in `--stdin`. `AT_HWCAP` now advertises PMULL, CRC32 and SHA3 (`0x20093`), checked against M3 known answers on every engine.
- **First-divergence readout (`#562`).** `ounce-core trace-diff --elf program.elf` prints the step, `pc` with `symbol+0xoff`, the decoded instruction, the differing registers side by side, and an NZCV/FPSR/FPCR split ([DIVERGE.md](https://github.com/hffgzktbcc-blip/ounce-core/blob/v0.12.0/docs/DIVERGE.md)).
- **Remaining scalar FP16 forms (`#558`).** `FRECPE`, `FRSQRTE`, `FRECPS`, `FRSQRTS`, `FABD` and the `FCM*`/`FAC*` compares, bit-exact against an Apple M3 over 595,472 cases covering the RN/RP/RM/RZ rounding modes, `DN`, `FZ` and `FZ16`.

**Important limits:** Ounce-Core supports bounded test workloads, not arbitrary ARM64 applications. Guests must be static, non-PIE and single-threaded (no `futex` or `clone`). `FEAT_AES`/`SHA1`/`SHA2` and `LDXP`/`STXP` are not implemented. Matching results apply to the inputs tested, and **no external developer has independently reproduced these release results yet** ([LIMITS.md](https://github.com/hffgzktbcc-blip/ounce-core/blob/v0.12.0/docs/LIMITS.md)).

See the [full changes from v0.11.0](https://github.com/hffgzktbcc-blip/ounce-core/compare/v0.11.0...v0.12.0) and [CHANGELOG.md](https://github.com/hffgzktbcc-blip/ounce-core/blob/v0.12.0/CHANGELOG.md).

## Library runs (23–24 Nov 2026, Apple M3)

Seven libraries built as static AArch64 Linux ELFs at `-O2` and `-O3 -mcpu=apple_m1`, run on the interpreter, Tier-3 and Tier-4, and compared with a native M3 build or the suite's own checks. The [evidence page](https://github.com/hffgzktbcc-blip/ounce-core/blob/v0.12.0/docs/verify/bigtech-2026-11-23.md) gives commits, flags, oracles and commands. The runs were made by Claude agents under Orca on the maintainer's machine; they are not an independent reproduction.

| Library | Result |
|---|---|
| BLAKE3 | 822/822 at both levels, all engines |
| libmpdec 4.0.0 | 148/148 test files at both levels, all engines |
| s2n-bignum | 384 passed, 0 failed, **13 skipped** (need `FEAT_AES`) at both levels, all engines |
| simdjson | 6/6 at both levels, all engines (`-O3` only after `#559`) |
| libwebp | 57/57; the `-O3` interpreter run was not done |
| secp256k1 | 119/119 on Tier-4 at both levels; **the Tier-3 and interpreter runs did not finish** |
| SGP4 | 962/1,222 lines bit-identical to a macOS-libm oracle; the rest differ by 1–2 ulp (median), unclassified |

## Technical changes

- **CPU (`#558`, `#559`):** scalar FP16 reciprocal/rsqrt estimates and steps, `FABD` and compares; `FEAT_LSE` atomics and `LDAPR`. The decoder now routes encodings it does not implement to an unimplemented-instruction stop instead of a neighbouring load/store form, so `LDXP`/`STXP` stop rather than run wrongly.
- **Linux runner (`#557`):** argument parsing for `run-elf -- <elf>`; the syscalls listed above; a scratch file system capped at 64 files, 64 open descriptors, 16 MiB per file and 64 MiB in total, with no host writes; and the bad-syscall test fixture moved to `bpf` (280).
- **Diagnosis (`#562`):** `trace-diff --elf`. JSON gains a `readout` object only when `--elf` is passed; existing fields are unchanged.
- **Docs and tests (`#560`, `#561`):** Quick Start runner instructions, current limits, the dated library-run page, and Windows line endings pinned for the known-answer fixture.

## What this release does not claim

- The library runs show agreement on the listed inputs and flags, not general correctness of the libraries or of Ounce-Core.
- The SGP4 differences are attributed to macOS versus musl `libm` but not verified; no libm-independent oracle exists yet.
- Multi-threaded, dynamically linked or PIE Linux programs remain out of scope.
