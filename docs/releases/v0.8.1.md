# Ounce Core v0.8.1

A small fix release for two problems found by the ounce-hb project's end-to-end tests. Verification and
conformance claims are unchanged: nothing here claims independent reproduction, Neoverse conformance or general
libc compatibility.

## Fixed

- `run-nro` and `run` now refuse a guest argument string longer than 62,855 bytes, with a `[Loader Error]` and exit
  code 1, before the program starts (#418). The string is the program path (`sdmc:/<file>`) and the guest arguments
  joined by spaces. Before, a longer string overwrote the program's first instruction, so the program executed the
  argument text. With the old binary, 62,839 bytes worked and 62,840 failed.

## Changed

- `--present=headless` (or `OUNCE_PRESENT=headless`) opens no host audio device, so a run on a machine with no
  audio output no longer prints ALSA or `[HostAudioSink]` errors to stderr (#419). Guest audio is discarded in that
  mode. The other presentation modes still open the default output device (#421).

## Removed

- The release no longer includes a prebuilt Mac app. The app stays build-from-source (`docs/MAC_APP.md`). This
  release has the Linux, macOS and Windows command-line archives and `SHA256SUMS`.

## Checked

- CI passed on both changes before merging: 44 of 44 checks for #420 and 44 of 44 for #421.
- The 62,855-byte limit is covered by loader unit tests at and one byte over the limit, and by CLI tests on Linux
  and macOS. The CLI tests are skipped on Windows because Windows caps a command line at 32,767 characters.
- That headless runs skip the audio device is covered by a unit test that needs no audio hardware. It was not
  reproduced on a machine without an audio device by the author; the Linux CI runners have none.
