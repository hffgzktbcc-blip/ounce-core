# Decoder census, 2026-11-08

Which AArch64 words in real programs does `decode` (src/cpu/decoder.rs) turn into
`Instruction::Unimplemented`, ranked by how often they occur. Measured on origin/main `174c6f2`.

Reproduce:

```
ounce-core census --top 30 ~/Projects/Ounce-Core-Samples \
  ~/Projects/ounce-lz4/{harness/lz4_harness,xxh/xxh_harness,sql/sql_harness,lua/lua_harness,fp/fp_cases,narrow/narrow_cases}.nro
```

Options: `--min-count N`, `--json`, `--top N`, `--mask HEX`. Inputs are NRO files (text segment) or
AArch64 ELF files (all executable PT_LOAD segments); directories are walked for `*.nro`/`*.elf`.

## How to read it

- A class key is `word & 0xFFE0FC00`: bits 31..21 and 15..10 are kept, Rd/Rn (4..0, 9..5) and
  bits 20..16 (Rm or an opcode/immediate field) are masked. Same class means same top-level
  encoding shape with different registers. Bits 20..16 are masked, so a class can hold several
  mnemonics (rank 4 holds both FCVTZS and ADDV), and `--mask` lets you re-cut it.
- `example` is the first word seen. The mnemonic list below was produced by running
  `aarch64-none-elf-objdump -D -b binary -m aarch64` over every word in the class
  (all 26 NROs; the same code as the matching `.elf` files, which have symbols).
- Counts are static occurrences in text, not execution frequency. A class that is rare in text
  can still be hot in a loop, and the reverse.

## Caveats (false positives)

- Text segments contain data: literal pools, jump tables, alignment padding. Rank 1
  (0x00000000, 88,891 words, 91.7% of all undecoded) is almost entirely zero padding
  (88,830 exact zero words), not missing instructions. Ignore it.
- Data words can look like any class; low-count classes (under about 5) are more likely data
  than code. Use `--min-count`.
- A decodable word that shares a class key with an undecoded one is not counted as undecoded;
  the key is a grouping aid, not an exact decoder predicate.
- `Unimplemented` also covers truly undefined encodings.
- Samples are mostly libnx/devkitPro C and C++ plus six harnesses, so SIMD-heavy code from the
  harnesses (lua, sql, narrow, fp) is overrepresented relative to games.

## Surprises

- Zero padding is 92% of the "undecoded" words, so the real undecoded rate on instructions is
  about 0.2%.
- Vector FP compares (FCMGE/FCMEQ/FCMGT) are the largest real gap.
- BRK, a plain system instruction, is undecoded.
