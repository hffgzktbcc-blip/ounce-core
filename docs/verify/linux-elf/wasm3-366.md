# wasm3 static musl ELF: guarded virtual memory (#366)

The pinned, unmodified MIT wasm3 harness at `28ecb9af6d2040e474a70f7cb7f43666740141fb`
uses guarded linear memory on 64-bit POSIX. `Guard_Reserve` in upstream `m3_core.c`
reserves `(8 GiB + two host pages) * 128 = 0x10000100000` bytes; `m3_HostReserve`
in `m3_host_posix.h` requests anonymous `PROT_NONE | MAP_NORESERVE` address space.
It halves the slot count if reservation fails. This request is from wasm3 itself,
not from a corrupted musl malloc size. Committed memory starts with a single header
page and grows through `mprotect`; no terabyte of page buffers is needed.

## Reproduce

```sh
python3 -m venv /tmp/wasm3-venv
/tmp/wasm3-venv/bin/pip install ziglang==0.17.1
cargo build --release --locked --features native-jit
python3 scripts/verify_linux_elf.py --harness wasm3 --budget 4000000000 \
  --work /tmp/wasm3-new-evidence --host-cc cc \
  --elf-cc '/tmp/wasm3-venv/bin/python -m ziglang cc -target aarch64-linux-musl'
```

Use a new work directory each time. On non-ARM64 hosts add `--qemu qemu-aarch64`:
the same ELF under qemu is the reference, since default NaN signs differ between
x86 and AArch64. The Linux CI differential matrix now includes this command with
qemu. An ARM64 host build is the local hardware reference; no output normalization
or wasm3 configuration change is applied.

## Diagnosis and implementation

Before the repair both actual engines exit 1 after **357,384 instructions** and
30 syscalls, printing `fib load memory allocation failed`. The first reservation
and every halved attempt are rejected by the old 512 MiB eager-mapping limit.
There is no `brk` or `mremap` call before that failure. The first two anonymous
allocations are `0x10108` and `0x1f000` bytes, at `0x400000000000` and
`0x400000011000`; the latter loses its `0xf000` prefix to a successful `munmap`.
That is allocator alignment trimming. A different placement can legitimately
change the trim length; it does not explain the later intentional arena request.

The runner now keeps virtual mapping intervals separately from backed MMU pages.
Reservations consume an interval, and overlap checks include them. Anonymous fixed
mapping and unmapping split intervals and discard only existing page buffers.
`mprotect` validates the complete range before committing, preserves existing
bytes, and limits newly accessible backing; changing to `PROT_NONE` preserves
already committed bytes, whereas fixed anonymous replacement resets them to zero.
The 512 MiB per accessible request and 1 GiB anonymous backing limits remain.
Large unmaps inspect existing pages rather than walking every virtual page.

Guarded wasm3 also needs the actual installed signal dispositions to round-trip,
an alternate signal stack, masks, and synchronous guest SIGSEGV delivery. The
runner builds a Linux AArch64 `rt_sigframe` with siginfo, ucontext and FPSIMD state;
handlers can return through `rt_sigreturn` or leave through musl's `siglongjmp`.
`gettid`, read-only stack limits, and musl's non-moving `mremap` stack probe complete
its stack-discovery path. No host signals or unsafe Rust are used.

After these changes an initial full run exposed one additional real discrepancy:
`mem.sum 00010000` was `00000cda` instead of `00000cfc`. A store crossing from a
committed page into the guard modified its accessible prefix before faulting.
Cross-page writes now validate all page permissions before changing bytes or code
invalidation generations. This restores the unchanged expected memory sum.

## Regression coverage and limits

`tests/linux-elf/src/guarded_memory.c` reserves the full arena, commits one page,
checks permission toggles preserve bytes, installs and queries an SA_SIGINFO
handler on an alternate stack, returns from repeated faults, verifies a crossing
store has no partial effect, and checks fixed decommit/commit yields zeroes.
The Rust Linux tests run it on interpreter, Tier-3 and Tier-4; native-jit builds
exercise the actual JIT. Unit tests cover sparse allocation counts, oversized
commit refusal, holes, hint overlap, fixed trimming, overflow, and store fault
atomicity including code-cache generations.

This is a single-threaded Linux subset: asynchronous delivery, general signal
sources, SS_AUTODISARM, and a general resource-limit API are not implemented.
`mremap` of sparse reservations is not supported. The local machine is macOS ARM64
and has no qemu-user; the original issue's qemu observation was not independently
rerun locally. Linux CI provides the same-ELF qemu comparison.


## Local verification (2026-11-14, macOS ARM64)

The fixed verifier run matches all **14,766 lines / 727,018 bytes** of fresh host
stdout on both actual engines, exiting 0. Tier-3 executes 224,870,100 instructions;
Tier-4 executes 224,869,990; both make 1,277 syscalls. The small instruction-count
difference reflects engine execution accounting; stdout and exit status match.
The [machine-readable evidence](wasm3-366-evidence.json) records identities and
results, including the preserved failed baseline and the intermediate memory-sum
failure. ELFs and fetched third-party sources remain outside the repository.

LZ4, xxHash, cJSON, SQLite and Lua also match fresh host stdout on both engines.
Full Rust suites pass: 614 unit tests without native-jit and 644 with it (11
ignored in each), plus all 27 integration tests in each configuration. The Python
verifier suite passes seven tests; legal guardrails and `git diff
--check` pass. Full Rust suites use the normal test profile with only this package
optimized (`--config 'profile.test.package.ounce-core.opt-level=2'`), retaining
debug assertions and overflow checks. Unoptimized attempts were stopped while
the existing corrupted-header instruction-budget test ran; expectations were not
changed. An intermediate optimized run caught the new preflight's last-address
arithmetic overflow in two existing tests; the corrected addition groups `len-1`
before adding it to the address.
