# Issue #414: Apple M1 xxHash after FEAT_SHA3 support

On 2026-11-13, on an Apple Silicon macOS host, the unchanged pinned xxHash harness
built with Zig 0.17.1, `-O3 -mcpu=apple_m1 -target aarch64-linux-musl`, exits 0 on
both `--cpu=tier3` and `--cpu=tier4`, prints `fails=0`, and matches the host stdout
byte for byte. The upstream pin is `2ec67caeb18ec15ae60c0853174331089acddfc0`.
The harness and its cases were unchanged. This is a command-line run, not a new
Mac app UI verification; the older screenshots remain historical evidence.

The retained pre-fix repro ELF (SHA-256
`619d6fc6838eebc7a3acd85997b875577e8904a330134ef0123b8343f9e3dc12`), which previously
stopped at `0xce000e10`, now completes 247,743 instructions on each engine. A
fresh build with the same compiler flags completes 247,733 instructions on each
engine (ELF SHA-256
`f2a1c86c7f5cb2c7b9b7fc01538ffd0ded00042ac32c8bd24436d06dd9c1a3a8`). Both outputs
match the host and each other; stdout SHA-256 is
`9be43696766caa25981038753037e18d273862a6b58aeccd8f02e34829d841b2`.
Build paths differ between the two binaries.

## Reproduce

Install `ziglang==0.17.1` in a Python venv, then use that venv's Python below.
Run from the repository root (choose a new work directory):

```sh
cargo build --release --locked --features native-jit
python3 scripts/verify_linux_elf.py --harness xxhash --work /tmp/sha3-xxhash \
  --host-cc cc --elf-cc 'python3 -m ziglang cc -target aarch64-linux-musl'
cd /tmp/sha3-xxhash
python3 -m ziglang cc -target aarch64-linux-musl -O3 -mcpu=apple_m1 \
  -Isources -static -no-pie sources/host_main.c sources/xxh_cases.c sources/xxhash.c \
  -o xxhash-m1.elf
/path/to/ounce-core/target/release/ounce-core run-elf xxhash-m1.elf --cpu=tier3 > m1-tier3.stdout
/path/to/ounce-core/target/release/ounce-core run-elf xxhash-m1.elf --cpu=tier4 > m1-tier4.stdout
cmp host-run.stdout m1-tier3.stdout
cmp host-run.stdout m1-tier4.stdout
tail -1 m1-tier3.stdout # fails=0
```

## Execution coverage

EOR3 and BCAX operate on all 128 bits; RAX1 and XAR operate independently on both
64-bit lanes. Tier-1, cached Tier-2 and warmed/fused Tier-3 execute the same decoded
semantics. Tier-4 explicitly hands these instructions to its existing Tier-3
fallback without partially updating registers. Native lowering of SHA3 itself is
not claimed. Tests include the exact EOR3 repro word, every XAR immediate, distinct
high/low input lanes, destination/source aliases (including V31), preserved FPSR,
and a native prefix followed by SHA3 fallback.

The other quick pinned harnesses from the Mac app report were rebuilt with the
standard `-O1` ELF flags: LZ4, cJSON, Lua and SQLite all exit 0 and match their
host stdout on both engines. Zlib initially exhausted the verifier's default
100,000,000-instruction budget on both engines; the same ELF, rerun with
`--max-insns=1000000000`, exits 0 on both after 313,690,546 instructions and matches
the host stdout. The failed budget-limited reports were preserved. wasm3's known
allocation failure was not revisited. No new GUI or independent third-party
verification is claimed.
