# Stress results, 2026-11-08 (macOS arm64, release build with `nce native-jit`)

Tool: `scripts/stress_nro.py` (see its `--help`).

**Samples.** The 20 sample programs (`~/Projects/Ounce-Core-Samples`, built outside homebrew) each ran headless with a 3,000,000-instruction budget:
- Tier-3: 20 of 20 ran to the budget with no VM error, panic or signal.
- Tier-4: 20 of 20 the same.
- Native: all 20 were still running at the 40-second wall-clock cap. They are interactive programs waiting for input and the native engine has no instruction budget, so this shows a missing time limit, not a failure. A wall-clock cap for `--cpu=native` would make it usable in CI scripts.

**Loader fuzz.** 300 corrupted copies of the sample programs (seed 1234: truncation, random header bytes, random body bytes, zeroed runs of up to 4 KB), Tier-3, 500,000-instruction budget, 30-second cap: 0 Rust panics, 0 host signals, 0 hangs. Bad inputs end in a reported `[VM Error]`, a loader error, or normal exit.

**Not covered.** Native execution was not fuzzed: a corrupted guest runs on the host CPU there, so the question is whether the host-side sandbox holds, which needs a separate, careful test. GPU and audio paths were headless. Mutations are random, not coverage-guided.
