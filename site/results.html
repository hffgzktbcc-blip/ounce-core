Each program was built twice from a pinned version: once for a normal computer (the reference, on Apple Silicon, which is real ARM64) and once as an ARM64 program run in Ounce-Core on three engines. The text output was compared byte for byte. Every folder under docs/verify holds the test source, the reference output and the per-engine result.

How to read this

Editorial note (9 November 2026): this table is a historical selection, not a complete live harness inventory. The unmerged proposals above are marked closed, not merged; see the current harness manifest, latest status and limitations before quoting a result.

Maturity: bounded-verified. Output matched the reference on the inputs tested, with the evidence kept. It does not show a program or the emulator is correct everywhere, and no one outside the project has repeated it yet. The native engine runs on the host CPU, so on an ARM64 machine the Tier-3 interpreter and the Tier-4 JIT are the real evidence.

Not covered: many vector, floating-point and system instructions are still undecoded or untested; FPCR rounding, flush-to-zero and default-NaN are modelled for common FP forms, but FP exception flags (FPSR), trap enables and half-precision arithmetic are not; the emulator is not fast (roughly 20 million instructions per second); a bounded static AArch64 Linux ELF runner has merged (18 programs run; wasm3 does not yet), but arbitrary ARM64/Linux application compatibility is not established.

Robustness: 300 corrupted programs through the loader produced no panics, signals or hangs on the interpreter engine; native was not fuzzed.
