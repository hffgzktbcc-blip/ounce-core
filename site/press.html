Ounce-Core press & research kit

For technical writers, researchers and prospective testers seeking accurate, dated descriptions of Ounce-Core. Please use the specific CI run and commit being described rather than an uncited headline number.

Short description

Ounce-Core is an open-source Rust ARM64 execution lab: it runs programs on several CPU engines and checks the results against real ARM64 hardware. It grew out of a Switch homebrew runtime; that is no longer its goal.

What can be claimed today?

  • Unmodified open-source programs (LZ4, xxHash, SQLite, Lua) and a floating-point instruction test produce output identical to an Apple Silicon reference on three engines; this found and fixed a dozen CPU bugs. See the verification folder.
  • A regression corpus of 50 pinned Switch-era homebrew programs passes in CI. It does not show Switch or Switch 2 compatibility.
  • External copies, questions and issue reports are public indicators of attention; they do not establish independent successful execution.

What is not proven?

Coverage is partial and the tests show agreement on the inputs used, not general correctness. Do not describe it as a Switch or Switch 2 emulator, a fast emulator, or a replacement for QEMU; Switch 2 work is parked per PLAN.md. No retail or commercial software is run or supported.

Recent developments to report carefully

Since the early differential harnesses, the standalone ounce-diagnose v0.2.0 failure-to-reproduction toolkit (diagnosis-v0.2.0 release, CLI guide, SDL2 walkthrough, libnx #685 audio-channel case), a bounded static Linux AArch64 ELF runner (PR #255), LZ4 ELF test workflow (#263) and web verification lab (#261) were shipped. These are experimental tools, not unrestricted Linux application support. The vector-multiply NaN investigation in #267 was resolved for the retained FMUL case. For any article, confirm the exact workflow run and scope before calling a result a pass.

Independent testers wanted

Our CI results are internal: they were produced by the project's own workflows. No outside reproduction has been reported yet. Researchers with an ARM64 machine are invited to follow the reproduction guide, record the outcome with the external test report template, and report it on issue #248. Matching results and failing results are both useful.
